## Deploy order

1. **`_shared/`** - create the S3 bucket and the Glue service role. Once per account/environment.
2. **Per-job bundles** - upload `scripts/` and `data/`, then deploy the job stack. Any order, in parallel if you like.
3. **Orchestration** - wire up the pipelines listed below that need loops or branching.

```bash
cd _shared
aws cloudformation deploy \
  --stack-name adf-glue-migration-core \
  --template-file cloudformation/00-core-bucket-and-role.yaml \
  --capabilities CAPABILITY_NAMED_IAM \
  --parameter-overrides ProjectBucketName=my-adf-glue-migration-bucket
```

Then for each job bundle, follow its README (steps 1-5).

## What was generated how

- **Glue PySpark scripts** - generated by the `openai-gpt-5-mini` LLM from the ADF activity
  graph, then validated with `ast.parse` and structural checks, with automatic
  repair rounds on failure.
- **CloudFormation and IAM** - rendered deterministically from the LLM's migration
  plan, not generated as free text, so no stack template can contain an invented
  resource type.
- **Secrets** - never copied out of Azure. Every credential is expected in AWS
  Secrets Manager under the `glue/adf/` prefix.

## Before production

Every generated script is a strong starting point, not a finished migration.
Confirm: JDBC drivers and connection details, network paths from Glue to your
data stores, partitioning and write modes, and each job's IAM policy.
